## Full-model comparison

Same release executable, GGUF, synthetic prompt IDs and settings for both arms. Metal 4 tensor FP16 baseline versus opt-in INT8, six AB/BA cycles, pp128/pp512, 32 decode steps, warmup 512, four CPU threads. Actual INT8 dispatch counts must be nonzero in the native arm and zero in the baseline; these counters are cumulative and include warmup. RSS is sampled after each point; backend bytes come from Metal `currentAllocatedSize`. Both are MiB, not a peak-memory profiler; do not add RSS and Metal bytes. INT8 retains original mapped weights and adds grow-only scratch of `(rows + n_out) * (K + 4)` bytes for row-scaled prepared X and W, including FP32 scales. The scale is the smallest power of two covering `amax / 127` (minimum normal FP32). Zero rows use scale 1. This adds both activation and weight error and does not reduce model storage.

## Initial blockwise implementation

An earlier implementation preserved arbitrary original GGUF weight block scales and used 32-term integer dots with FP32 rescaling, quantizing activations per block. Its best row tile was 64. That exploratory run warmed 16 tokens; the final run warms 512 to exercise native preparation before timing. The final implementation prepares rows once and uses full-K integer dots with one post-scale. Each implementation has its own same-binary FP16/INT8 comparison; revisions and executable hashes are recorded separately. This exploratory comparison is not a clean-revision A/B performance gate.

| Model | Prompt | Initial INT8 / FP16 | Final INT8 / FP16 |
|---|---:|---:|---:|
| qwen3-q8 | 128 | 0.281× | 0.710× |
| qwen3-q8 | 512 | 0.255× | 0.817× |
| qwen35-q8 | 128 | 0.321× | 0.733× |
| qwen35-q8 | 512 | 0.292× | 0.867× |
| llama3-q4k | 128 | 0.185× | 0.440× |
| llama3-q4k | 512 | 0.180× | 0.635× |

The isolated GEMM advantage is real on these controlled inputs, but preparing weights/activations and reading expanded temporary matrices still costs time and memory. The final path avoids per-block FP32 rescaling inside GEMM, at the cost of coarser rowwise quantization. K is capped at 65,536 to bound worst-case INT32 sums. A separate native INT8/E8M0 scale-plane prototype compiled but did not complete GPU dispatches on this driver within the test timeout; it was discarded and is not in this PR. The completed comparisons use ordinary INT8 tensors and explicit post-scaling.

## Reproduce

```sh
python3 tools/bench_metal_precision.py --out /tmp/m6/isolated
python3 tools/bench_metal_int8.py --tune-only --model NAME=/path/to/model.gguf --out /tmp/m6/tuning-rowwise
python3 tools/bench_metal_int8.py --tile-rows 128 --model NAME=/path/to/model.gguf --out /tmp/m6/models
python3 tools/report_metal_int8.py benchmark/results/raw/m6-int8-2026-11-01 --out benchmark/results/M6_INT8.md
```

Run measurement commands under an exclusive host lease. Build commands and scope are in `docs/BACKENDS.md`. The generator also reads the recorded initial blockwise run; that run can be reproduced at its recorded revision.
